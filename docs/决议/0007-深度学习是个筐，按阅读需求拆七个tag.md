# 0007「深度学习」是个筐，按阅读需求拆成七个 tag

状态：Accepted（2026-09-13）

## 背景

[0003](0003-收录范围扩到机器学习干货与数学.md) 把范围从搜广推扩到「机器学习/深度学习
干货 + 数学分析」，当时新建了「数学」tag，理由写得很清楚：挂到「深度学习」下面是误导，
用户点那个 tag 想看模型结构，刷出来的是半正定矩阵合同对角化。

[0004](0004-词表要随批次修，判据是一手还是转述.md) 又建了「大模型Infra」，
[0005](0005-收录范围再扩到跨领域干货，判据加一条导流.md) 建了「数理物理」和「量化金融」。
三次都是同一个动作：**发现某个 tag 里装着两种不该混在一起的阅读需求，就拆一个出来。**

到 2026-09-13 这批 92 人入库之后，「深度学习」变成了 33 源的筐，而且它的性质和前三次
不一样——前三次拆出去的是**明显不属于这里**的东西（数学、物理、Infra），这次剩下的 33 个
源本身确实都在讲深度学习，但讲的是四种互不相干的方向：

| 谁 | 在写什么 |
| --- | --- |
| 赵世钰-西湖大学、强化学习实验室 | 多智能体强化学习做无人机协同追逃、灵巧手从仿真学力度控制 |
| 来一块葱花饼、VincentLee | 目标跟踪顶会笔记、图像检索综述、通用分割模型 |
| 泽宇、胡伟 | 知识图谱推理综述、联邦知识图谱表示学习 |
| 吃果冻不吐果冻皮、Chaos AI Studio | InfiniBand 与 SHARP 网络内计算、ZeRO 三级与算子融合 |

点开「深度学习」想看模型结构，刷出来的是无人机编队和 GEMM kernel。**这和 0003 排数学
的理由是同一个，只是这次四种方向都是深度学习，所以一直没被当成问题。**

## 决策

### 一、拆七个 tag，判据是「点开这个 tag 的人想看什么」

不按论文分类体系拆，按阅读需求拆。用户 2026-09-13 点名的领域是
「广告算法、搜索算法、CV、NLP、大模型、强化学习、多模态，甚至数据分析、金融量化研究」，
拆出来的 tag 就贴着这份名单，另加两个是库里实际内容逼出来的：

| 新 tag | 拆完源数 | 点开想看什么 |
| --- | --- | --- |
| 强化学习 | 12 | RL 训推框架、GRPO 排查、策略梯度推导、多智能体控制 |
| Agent | 13 | Coding Agent 架构、上下文工程、Skills 与 MCP 的取舍 |
| NLP | 11 | 知识图谱与 RAG、模型结构解读、技术报告评论 |
| 多模态 | 5 | 扩散与视频生成推理、投机解码、VLM |
| 具身 | 5 | VLA、世界动作模型、运动生成与运动学、机器人策略学习 |
| CV | 4 | 目标跟踪、图像检索、语义分割、源码解析 |
| 数据分析 | 2 | A/B 测试与因果推断、归因、CLV 与生存建模 |

「具身」不在用户给的名单里，但 tomsheep 的具身智能十讲和强化学习实验室的灵巧手内容
既不是 CV 也不是纯 RL，硬塞进任何一个都会让那个 tag 变味。

**拆完「深度学习」剩 6 个源**，指的是既不属 CV/NLP/RL 也不属 Infra 的通用内容：
科学空间（苏剑林，优化器与扩散的数学）、繁凡（元学习、信息熵、逻辑回归笔记）、
周舒畅（扩散模型与机器人算法的数学推导）、AI4Science探索（PINN 物理驱动建模）、
学习成瘾（Krylov 子空间与 PDE 弱形式）、蒹葭苍苍（反向传播与 RNN 的关系）。
这个 tag 现在名副其实了。

### 二、多 tag 是常态，不强求归一类

一个源挂多个 tag 不是分类不清，是内容本来就跨。39 个源被重分（38 个知乎源 + 1 个 GitHub 策展仓 Awesome-CTR-Scaling，它入库时误挂了「深度学习」，改成「搜广推 + 生成式推荐」），其中 31 个挂了两个以上：

- 猛猿 → 大模型Infra + 多模态 + 强化学习（图解 vLLM 的 KVCacheManager、异步 RL 框架
  AReaL 速览、Qwen2.5-VL 实现细节）
- 北京智源人工智能研究院 → NLP + 多模态 + 具身（Emu3.5 世界模型、Reason-RFT 视觉推理、
  RoboBrain 2.5）
- 赵世钰-西湖大学 → 强化学习 + CV + 具身（多智能体强化学习 + 3D 视觉检测做无人机运动估计）
- Chiahsin → 搜广推 + 数学 + 数据分析（Adtributor 归因、期权定价推导、布朗运动与伊藤公式）

判据是：**这个 tag 下的人刷出他的内容，读者会不会觉得跑题。** 会就摘掉那个 tag。

### 三、主领域归类只用于对账，不写进库

为了回答「收了多少人、都是什么领域」，把 92 人按主要方向各归了一类（一人一类，
不重复计数）：大模型Infra 24、数学 22、搜广推 13、NLP 9、强化学习 7、数理物理 7、
Agent 4、机器学习通用 3、具身 1、CV 1、数据分析 1。

**这份归类不落进 `data/subscriptions.json`**，库里的 tag 是多值的，按一人一类存会丢信息。
它只存在于本机 vault 的 `Contents/RecSearch/Sources.md` 第 4 节的分领域表里
（本机路径不外发，故此处只写 vault 内相对路径），
用途是回答「库里有什么」，不是用来筛河。筛河用 tag。

归类时改过三个判断，记下来免得下次重犯：

- AI4Science探索、周舒畅、繁凡 一开始归了 CV，实际写的是 PINN 物理建模、
  扩散模型的数学推导、通用深度学习笔记，归「机器学习通用」。
- tomsheep 一开始归了 CV，实际是 VLA 简史、世界动作模型、具身智能十讲，归「具身」。
- 赵世钰-西湖大学 一开始归了 CV，主线是多智能体强化学习，CV 是手段，归「强化学习」。

### 四、tag 清单要同步进工具，否则下次导入会被拒

`tools/zhihu-import.js` 的 `KNOWN_TAGS` 是白名单，不在里面的 tag 会让整条导入失败
（`未知 tag：X`）。七个新 tag 已经加进去，注释写明拆的理由和当时的源数。

漏这一步的后果很具体：下一批导入时想给某个人挂「强化学习」，工具会直接拒绝，
而错误信息里列的「已有 tag」还是旧的九个，看起来像是库不支持，实际是白名单没跟上。

## 后果

- tag 从 9 个变成 15 个（含空着的「量化金融」）。UI 的 tag 栏会变长，
  按源数降序排，拆完当日是「生成式推荐 35 / 数学 29 / 大模型Infra 27 /
  搜广推 27 / 推荐系统 27」仍在前排，新拆的七个（Agent 13、强化学习 12、NLP 11、
  多模态 5、具身 5、CV 4、数据分析 2）在后面。

  生成式推荐从 33 涨到 35 有两笔，都不是新收人：Awesome-CTR-Scaling 那个策展仓
  入库时误挂了「深度学习」，改成「搜广推 + 生成式推荐」；稳扎稳打学AI 是
  从信息源清单倒灌进来的公众号手动登记，挂「生成式推荐 + 搜广推」。
  **如果将来 tag 栏挤不下，
  做法是折叠到「更多」而不是合并 tag**——合并会把刚拆开的阅读需求重新混回去。
- 「深度学习」从 33 源降到 6 源。这是预期结果，不是丢源：那 27 个源都还在库里，
  只是换了更准的 tag。
- 数据分析只有 2 个源、CV 只有 4 个、具身只有 5 个。**稀疏 tag 的取舍在 0003 已经定过**：
  分组按内容分不按数量分，「信息检索」tag 当初只有 1 个源也建了。
- 库现在 160 源，`KNOWN_TAGS` 15 个。下一次扩范围时，先问一句
  「现有 tag 里有没有装着两种阅读需求的」，比先问「要不要建新 tag」更容易发现问题。
  这次「深度学习」装了四种方向而三个决议都没动它，就是因为前两次拆的都是
  「明显不属于这里」的东西。

## 遗留

1. **重分是手工判的，没有脚本。** 38 个源逐个看标题定的 tag，判据是上面第二节那句话。
   下次批量入库时还是得手工过一遍，`tools/zhihu-import.js` 只校验 tag 在白名单里，
   不校验 tag 挂得对不对。要做自动化的话，可以用 `tools/lib/wordlist.js` 的分支
   （它已经按 CV/RL/Infra/数学 分段了）反推 tag，但词表会漏，所以只能当初稿。
2. **多模态与具身的边界没定死。** 北京智源同时挂了两个，因为 Emu3.5 是多模态世界模型
   而 RoboBrain 是具身。将来源多了会需要一条明确规则，现在 5 个源还不值得定。
3. **「深度学习」这个 tag 名现在偏窄了。** 剩下的 6 个源里，学习成瘾写的是 Krylov 子空间
   与 PDE 弱形式，更接近数学；周舒畅写的是扩散模型的数学推导。等下一批进来，
   这个 tag 可能该改名叫「机器学习基础」或者继续往数学/数理物理分流。
