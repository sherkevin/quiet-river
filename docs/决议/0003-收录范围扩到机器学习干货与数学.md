# 0003 收录范围扩到机器学习干货与数学，判定改看扣噪后的技术密度

状态：Accepted（2026-09-13）

## 背景

[0001](0001-收录标准看专业性不看活跃度.md) 定的范围是搜广推，判定尺子是
`coreRatio`——标题里命中搜广推领域词（推荐系统、召回、精排、CTR…）的比例，门槛 15%。
[0002](0002-筛选要算覆盖率，简介不能当唯一证据.md) 补完了覆盖率，905 个关注
全部有了交代。

然后范围变了。2026-09-12 的要求是：

> 纯写机器学习跟深度学习干货的也可以纳进来。甚至做一些数学分析的也可以纳进来。

这句话把库从「一条搜广推行业情报河」改成「一条技术学习河」。改的不只是词表，
是三件事一起变：判什么、怎么判、tag 怎么分。

## 决策

### 一、判定指标从 coreRatio 换成 dryRatio

`dryRatio = 命中技术概念词且不属于噪声的标题数 / 总标题数`。

换指标的直接原因是：**范围一放宽，旧的假阳性模式立刻失效。** 用宽词表（把
`AI`、`大模型`、`RAG`、`Agent` 都算技术词）直接重判已扫的 319 人，排出来的是：

| 人 | 宽词表占比 | 实际是什么 |
| --- | --- | --- |
| 代码随想录 | 43% | LeetCode 题解 |
| 小林coding | 40% | 八股文面试资料 |
| 程序员吴师兄 | 37% | 刷题号 |
| 丁师兄大模型 | 43%（噪 43%） | 简介写明「大模型1v1辅导【面试陪跑】」 |

四个全是该排除的。根因是「标题里出现 RAG」和「在讲 RAG 本身」是两回事，
而范围窄的时候这个区别不重要——搜广推领域词（精排、双塔、竞价）本来就很难
在闲聊标题里凑出来。**范围一宽，词表必须自己承担区分度。**

所以 `dryRatio` 做了两件事，缺一不可：

1. **技术词表刻意窄。** 不收「AI」「人工智能」「大模型」，收
   `transformer`/`LayerNorm`/`策略梯度`/`半正定`/`奇异值分解` 这类具体概念。
   判据是：这个词只出现在标题里，能不能大概率说明作者在讲技术本身。
2. **扣噪声。** 命中 `NEWS`（如何评价X发布/盘点/速报）、`JOB`（面试/面经/辅导/读博申请）、
   `SALE`（公众号/知识星球/扫码领取）三类模式的标题，即使带技术词也不算干货。
   「RAG 落地最难的地方在哪」算，「大厂 Agent 面试的内幕」不算。

词表落在 `tools/lib/wordlist.js`，`tools/zhihu-rejudge.js` 和 `tools/zhihu-coverage.js`
共用同一份，免得两处口径悄悄走偏。

### 二、门槛重校准，从 15% 改成「过线后人工看标题」

0001 的 15% 是从库里既有源量出来的，尺子换了就得重量。用 `dryRatio` 量入库前
有标题缓存的库内知乎源：

| 源 | dryRatio | 旧 coreRatio |
| --- | --- | --- |
| 张峻旗 | 56% | 18% |
| 蘑菇先生 | 48% | 45% |
| RUC AI Engine | 35% | 15% |
| 武侠超人 | 25% | 25% |
| twilly | 24% | 19% |
| 美团技术团队 | 17% | 3% |
| 机器之心 | 3% | 0% |

两个结论：

- **新口径整体把数值抬高了**（技术词表比领域词表宽），所以 15% 对新范围太松。
  机器之心 3% 是资讯号，本来就该低。
- **但纯数字门槛在新范围下不可靠。** 数学号的「干货」和搜广推号的「干货」密度
  不一样：torsor 87% 全是高等代数证明题，而某个 40% 的号可能一半是「如何评价
  XX 模型发布」。占比相近，价值差很远。

所以这次的门槛是**两条腿**：`dryRatio >= 25%` 进候选，然后**人工看完标题样本**
才决定收不收。`tools/zhihu-rejudge.js --samples` 就是为这一步做的，它把干货标题
和噪声标题都打出来。

按这个流程，33 个 ≥25% 的候选里收了 22 个，排了 11 个；另外从 15-25% 档
按「干货绝对条数 >= 6」捞回 5 个（yang元祐、SiriusNEO、薛天帆、强化学习实验室、
微软亚洲研究院）。共 27 人入库。

这里有个一致性问题要说清楚：0001 定的原则是「新源不能按比库里既有源更严的尺子收」，
当时库内最低是 twilly 24%。这次收的 5 个人在 19-23%，低于 24%。
**不算违反**，因为 0001 约束的是同一把尺子下的相对宽严，而这把尺子换了；
换算的依据是看标题样本——yang元祐 19%（11/57）那 11 条是傅里叶变换、柯西积分公式、
数理方法讲义，密度不低于 twilly 24% 里混着追星内容的部分。

### 三、排除的是内容形态，不是占比

几个高分号被排掉了，记下来免得下次重新纠结：

- **鱼子酱 57%**：标题全是「杀疯了」「夯爆了」「速看」「这波风口值得追」。
  内容是论文导流，正文在公众号。占比高，但是营销文体。
- **master学堂 47%**：全是量化交易研报复现，「知识星球版」字样出现在标题里。
  内容是硬的，但属于另一个领域（量化投资），不在范围内。
- **丁师兄大模型 40%（噪 43%）**、**喜欢卷卷的瓦力 38%（噪 43%）**：噪声压过干货。
- **郭达森 38%**：内容全是「2021最新XX综述！」的标题列表，本质是论文索引站，
  停更于 2023-04。
- **大模型开发者社区 43%（噪 33%）**、**大模型粥粥 34%**、**人工智能技术干货 25%**：
  公众号搬运号，「一文搞懂」「保姆级」体。

反方向有一个**破格收录**，因为它正好说明占比不该是唯一标准：

- **LLMCat 29%（噪 39%）**：词表判它高噪声，是因为标题叫「LLM 面试官笔记 (1)-(6)」。
  但内容是 GRPO 训练崩溃的分层排查、CLIP 边界怎么调、策略坍塌的根因、
  去掉 std 归一化的代价——一手训练踩坑记录，不是求职内容。
  这是 `JOB` 词表的误伤（「面试官」命中了求职模式）。**词表错了就按人判，不改词表**，
  因为「面试官笔记」确实大多数时候是求职内容。

### 四、新建「数学」tag

`tools/zhihu-import.js` 原来的注释写「不新造 tag，多一个稀疏 tag 就多一个
只有一两张卡的分组」。这个前提这次不成立了：一次进 5 个纯数学源
（torsor、凇数、MathHub、马同学、yang元祐），写的是高等代数、微积分、数理方法。

挂到「深度学习」下面是误导——用户点那个 tag 想看模型结构，刷出来的是
「如何证明两个 n 阶半正定矩阵同时合同于对角阵」。**分组按内容分，不按数量分**，
而 5 个源也不稀疏（「信息检索」tag 当时只有 1 个源）。

入库后 tag 分布：生成式推荐 28、推荐系统 23、深度学习 23、搜广推 19、数学 5。

## 后果

- 库从 67 源涨到 94 源，知乎源 24 → 51。一轮刷新从约 4.2 分钟涨到约 8.9 分钟
  （每个知乎源约 10.5 秒，同宿主串行 8 秒间隔）。这是已知代价，仍可用。
- 库的定位变了：不再只是搜广推行业情报，也包含机器学习/深度学习和数学的
  学习材料。两类内容的阅读节奏不同——行业情报要追新，学习材料不会过期。
  目前内容河统一按时间倒序，学习材料会自然沉底，**暂时不为此做分组**，
  等真的觉得干扰阅读再处理。
- `dryRatio` 是初筛指标不是结论。词表会漏（没有词表能不漏）也会误伤（LLMCat
  就是一例），所以人工看标题这一步不能省。

## 遗留

1. **`tools/zhihu-coverage.js` 还没换词表。** 它内部的 `WIDE`/`CORE` 两个正则仍是
   搜广推口径，扫描文件清单写死到 result6。下一次对账前必须改成引用
   `tools/lib/wordlist.js`，否则「靠简介排除」那一刀在新范围下不成立——
   一个简介写「数学系博士」的人会被当成领域外。
   本次已经手工补了一遍：188 个文本排除者里，简介带科研/技术信号的只有 4 人
   （淡腾铲屎官二号、Triborg、kkhenry、孙悦礼，全是医学/量子科普），
   已组 batch16 实扫确认。
2. **batch9~15 还在扫。** 348 人里扫完 45 人（batch8），剩下的跑完后要用
   同样的流程重判，可能有增补。
3. **数学类源的内容会大量沉底。** torsor 最近发布 2025-11、马同学 2025-04、
   胡伟 2023-05，按时间倒序排在河底。0001 已经定了「活跃度不作为硬门槛」，
   所以这是预期行为，但实际阅读时数学 tag 下可能长期没有新内容。
