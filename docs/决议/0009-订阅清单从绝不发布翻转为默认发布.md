# 0009 订阅清单从「绝不发布」翻转为默认发布

状态：Accepted（2026-09-13）

## 背景

本仓此前的发布边界是刻意保守的：`tools/publish.sh` 的 NEVER 名单里第一条数据类
条目就是 `data/subscriptions.json`，`.gitignore` 里也留了「fork 推公开仓就取消注释」
的提示。理由写在旧注释里：清单是个人阅读清单，不该跟着代码公开。

2026-09-13 用户明确了新定位：**这个项目要成为别人也能直接用的开源项目，清单就是
产品的一部分**——「在我任何电脑上 clone 下来就能看到同一条河」。旧边界与新定位
直接冲突，必须显式翻转而不是悄悄改。

## 决议

发布物从「代码 + starter 源」变为「代码 + 作者完整清单 + 缓存快照」：

- `data/subscriptions.json`（170 源）进 ALLOW。
- 新增 `data/cache.seed.json`：每源最近 20 条、摘要截 400 字（与运行时
  `SUMMARY_LIMIT` 同值）、过脱敏闸。`store.loadCache` 在本机没有 `cache.json`
  时回落到它，clone 后第一次启动页面即满河。
- 快照生成器 `tools/make-seed.js` 与扫描器 `tools/scan-leaks.js` **不发布**：
  脱敏模式表就是「哪些串算本机痕迹」的索引，发布它等于发布扫描器的绕过指南。
- 登录态适配器（`lib/adapters.private.js`）、全量 `cache.json`、凭证、本机工具
  （publish/scan/make-seed、zhihu-* 遍历脚本）仍在 NEVER。这条不翻转：把平台
  反爬绕过写成公开代码的立场没变（README 第 3 档说明照旧）。

## 为什么快照只留 20 条而不是运行时的 60 条

快照是发布物，体积进 git 历史就永远在历史里。20 条/源 ≈ 1.7MB，够首屏与 tag
浏览；60 条/源 ≈ 3.6MB，多出来的两百万字节对「clone 即满河」这个目标没有边际
价值。能匿名抓的源在第一次刷新后就换成实时 60 条，快照只负责垫底。

## 后果

- GitHub 仓 sherkevin/quiet-river 从 private 转 public（不可逆，已执行）。
- 清单里的博主昵称、tag、平台分布从此公开。这是用户明确接受的：清单即产品。
- 在别人机器上，知乎 111 源与小红书 13 源是「读档」不是「活的」：没有凭证时
  刷新报「未知适配器」，`mergeIntoCache` 保留快照条目不清空，河不空只挂横幅。
  想在自己机器上激活：放自己的 `lib/adapters.private.js` 与 cookie（secrets/README.md
  有取法），小红书另需 opencli 登录态。
- fork 者想排除自己的清单：`.gitignore` 注释里留了开关，README 配置节写明。
- 扫描器升级为按 JSON 字段扫（单行大 JSON 按行扫会把每个 sha1 guid 报成凭证），
  标识符字段（guid/link/image 等）跳过；EXEMPT 收成 [串, 理由] 二元组，首批 5 条
  豁免全是抓来正文里被空格拆断的公开 URL 片段（NeurIPS PDF 哈希、Notion 页面 id）。
- 脱敏实测拦到过真东西：cache 里某条知乎回答正文含公司域名邮箱。快照继承 cache
  就继承它——所以脱敏闸不是形式主义，是发布快照的前提。该条在 20 条截断线外，
  但下一次刷新可能把它顶进快照，闸必须在。
