# 0004 词表要随批次修，判据是「一手实践」还是「转述报道」

状态：Accepted（2026-09-13）

## 背景

[0003](0003-收录范围扩到机器学习干货与数学.md) 定了 `dryRatio >= 25%` 进候选、
人工看标题定结论的两步法，收了 27 人。接着跑 batch9~16 的补扫，用同一把尺子
重判新出的候选人。

第一轮重判就露馅了：**分数和内容质量对不上，而且错的方向是一致的。**

## 决策

### 一、词表是随批次迭代的，不是一次定稿

`tools/lib/wordlist.js` 补了两段，都是被具体的人逼出来的：

1. **训练与推理 Infra**：`推理引擎`/`训推`/`PD分离`/`共卡`/`权重同步`/`算子融合`/
   `显存`/`MLSys`/`vLLM`/`SGLang`/`Megatron`/`rollout`/`梯度检查点`/`张量并行`/
   `CUDA`/`FlashAttention`/`投机解码`/`off-policy`。
   漏掉这一段的后果是：真正动手做系统的人，排不过只会转述模型发布的人。
2. **数学补漏**：`Krylov`/`有限元`/`PDE`/`弱形式`/`李群`/`李代数`/`平均场博弈`/
   `Koopman`/`逆强化学习`/`不动点`/`希尔伯特`/`度量空间`，以及信号与系统那一类
   （`小波`/`插值`/`sinc`/`冲激响应`/`Toeplitz`/`DFT`/`频域`）。
   信号与系统算数学分析的应用面，正是这次要收的内容。
3. **CUDA/通信层系统词**（batch10 补）：`GEMM`/`swizzle`/`bank conflict`/`CuTeDSL`/
   `NVSHMEM`/`DeepEP`/`DeepGEMM`/`RDMA`/`GPUDirect`/`NCCL`/`libfabric`/`Triton`/
   `通信计算重叠`/`fp8`/`AllReduce`。这一段的共同特征是：词只可能出现在真动手的
   标题里，资讯号凑不出来。
4. **集合论与数理逻辑**（batch10 补）：`集合论`/`数理逻辑`/`ZFC`/`选择公理`/`双射`/
   `可数`/`基数`/`序数`/`实变函数`/`勒贝格`/`抽象代数`/`同态`/`伽罗瓦`/`哥德尔`。
   漏这一支的后果是纯逻辑方向的人数学被系统性判低：beanandbean 20 条标题里
   15 条是集合论与数理逻辑，原词表只认出 4 条，因为这一支的术语（公理、双射、
   可数）和分析/代数那一支（矩阵、傅里叶）完全不重叠。补完 20% → 45%。

有一条刻意没收：`SIM`（Search-based Interest Model）。JS 的 `\b` 是 ASCII 词边界，
「SIM卡」这类标题会被误命中。**宁可漏一个模型名，也不要一个每次都误判的词。**

顺带修了一个**两个工具口径不一致**的 bug：`tools/zhihu-shortlist.js` 的
`TITLE_CORE` 早就有 `MMOE`/`ESMM`/`DIN`/`DIEN`/`出价策略`/`转化率预估`，
而共用的 `wordlist.js` 里一个都没有。所以「定西」被 shortlist 认出是搜广推博主
（命中词 `[MMOE,ESMM,DIN]`），却被 rejudge 判到 15%。两个脚本各拿一把尺子，
覆盖率对账（[0002](0002-筛选要算覆盖率，简介不能当唯一证据.md)）会因此漏人。

有一条刻意没收：`SIM`（Search-based Interest Model）。JS 的 `\b` 是 ASCII 词边界，
「SIM卡」这类标题会被误命中。**宁可漏一个模型名，也不要一个每次都误判的词。**

补完后分数回到了和内容一致的位置：直觉优先 45%→85%、学习成瘾 59%→77%、
kaiyuan 18%→48%、定西 15%→40%、beanandbean 20%→45%、陈乐群 20%→30%、
zzk again 15%→28%。BBuf 补完仍是 29%，因为它低的原因不是词表，见下一节。

### 二、占比低不等于不收，要看低在哪里

BBuf 补完词表还是 29%、方佳瑞 25%、SuSun 38%。按 0003 的两步法，占比只是初筛，
所以看他们那 70% 的非干货部分是什么：全是「如何评价 DeepSeek V4.1 Flash」
「怎么看 OpenAI 说 GPT-6 要做一次大扫除」这类**对模型发布的评论**——
被 `NEWS` 词表扣掉了，扣得对。

关键区别在于：**他们的干货部分是自己动手的结果，不是转述。**
BBuf 写「SGLang Custom AllReduce v1 与 v2 实现原理详解」，方佳瑞写
「为 Token-level 流水并行找 PMF：从 TeraPipe、Seq1F1B、HPipe 到 PipeFusion」，
SuSun 写「openinfer 0.1.0：当我用 Rust 写了一个生产级别的推理引擎」。
这种内容在别处找不到，而且不会过期。

所以这一批的判据明确成一句话：**看作者是在做，还是在说别人做了什么。**
「做」的收，哪怕夹了大量资讯评论；「说」的不收，哪怕占比很高。

### 三、新建「大模型Infra」tag

和 [0003](0003-收录范围扩到机器学习干货与数学.md) 建「数学」tag 同样的理由，
一次进 5 个源（emiya、kaiyuan、SuSun、BBuf、方佳瑞），写的是训推系统、
kernel、并行策略。挂到「深度学习」下面是误导：点那个 tag 想看模型结构，
刷出来的是「SGLang 中的 CUDA Graph 进阶指南」。分组按内容分，不按数量分。

入库后 tag 分布：生成式推荐 29、推荐系统 25、深度学习 24、搜广推 20、
数学 9、大模型Infra 5、信息检索 1。

（batch10 又进了 5 人，见后果一节，最终 tag 分布在那里。）

### 四、这一批排除的，记下来

- **鱼子酱 57%**：0003 已排，这轮分数仍是最高档。营销文体 + 公众号导流，理由不变。
- **具身之道RoboTao 21%**：内容是 VLA / 世界模型的**二手解读**（「XX 技术全解读」
  「万字拆解」），且领域是具身智能机器人；剩下的是留学申请、电影推荐。
- **JavaGuide 33%**、**ConardLi 28%**、**deephub 25%**：AI 编程工具与 Agent 用法
  的资讯聚合，技术概念词是蹭到的，不是在讲技术本身。
- **吴师兄学算法 28%**、**编程熊 27%**：LeetCode 刷题与华为 OD 备考辅导。
  和 0003 排掉的「代码随想录」同类。
- **微尘-黄含驰 19%**：69 条标题里 OpenClaw 相关 12 条、量化交易推广与
  「兼职天堂 700+元/小时」招聘信息、以及「有哪些神器 App」类问答。
  干货是有的（GRPO 自动对比闭环、PRM 接 GSM8K），但被冲得太淡。
- **Lily 32%**、**山河动人 33%**：技术内容占比不到四成，其余是「20 岁迷茫怎么办」
  「学历重要还是能力重要」这类泛问答。
- **动画讲编程 67%**：只有 3 条标题，样本不成立，且简介写明导流公众号 + QQ 群，
  最近发布 2020-09。**小样本不算数**，这条要一直记着。
- **定西**是这轮唯一的破格：40% 看着过线，但最近发布 2022-12-28，已停更三年多。
  仍收，依据是 0001「收录看专业性不看活跃度」——20 条全是经典论文解读，
  这些内容今天读照样成立。

## 后果

- 库 94 → 110 源，知乎源 51 → 67。这一轮（batch9 + batch10）入库 16 人：
  数学/信号 5（直觉优先、学习成瘾、林深见志、Control、beanandbean）、
  搜广推 2（tiantianheheaa、定西）、大模型Infra 9（emiya、kaiyuan、SuSun、
  BBuf、方佳瑞、陈乐群、KuangjuX、zzk again、Han Shen）。
  最终 tag 分布：生成式推荐 29、推荐系统 25、深度学习 24、搜广推 20、
  数学 10、大模型Infra 9、信息检索 1。
- 一轮刷新时间继续涨（每个知乎源约 10.5 秒，同宿主串行 8 秒间隔），
  110 源约 18 分钟。仍在可用范围，但**再往上涨就要考虑只刷新用户当前在看的 tag**。
- 词表现在有 200+ 条正则，且会随批次继续长。它只做初筛，人工看标题这一步
  反而更重要了——分数越不可信，人眼越是唯一可靠的判据。

## 遗留

1. **batch10~16 + calib 还在扫。** 扫完后用同一流程重判。词表这轮改过，
   前面批次（1~8）的人分数也变了，`zhihu-rejudge.js` 是重算落盘 JSON 的，
   不重发请求，所以旧批次自动跟着新词表走，不用重扫。
2. **calib 批跑完后要重算门槛叙事。** 0003 里那张库内源占比表（张峻旗 56%、
   蘑菇先生 48%…）是旧词表量的，现在全部要重新量一遍。
3. **`tools/zhihu-shortlist.js` 的 TITLE_CORE 应该改成引用 wordlist.js。**
   这轮已经发现两处口径不一致，手工补平了一次，下次加词还会再犯。
   等扫描全部跑完再做，中途改会让正在跑的批次换尺子。
