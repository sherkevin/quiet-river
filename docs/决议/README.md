0016 是同一天的自我纠错：0014 只查了「Miniflux 能不能拉内网」（出向），
没查「外部能不能推进去」（入向）。导入接口 `POST /v1/feeds/{feedID}/entries/import`
是纯数据库写入，不经过抓取器，所以私网拦截在这条路径上不参与判断。
两份都留着，0014 记录的是这个推理错误的形状。

这个目录**已进** `tools/publish.sh` 的发布白名单（2026-09-17 翻转）。

原先不发布的理由是「决议里有具体博主的昵称与内容构成，和
`data/subscriptions.json` 同级处理（后者在 NEVER 名单里）」。
**这条理由在 [0009](0009-订阅清单从绝不发布翻转为默认发布.md) 之后就已经失效了**：
0009 把订阅清单从「绝不发布」翻转成默认发布，理由是「清单就是产品的一部分」。
公开仓里的 `data/subscriptions.json` 确实带着 271 个源的博主昵称
（实扫确认），所以「决议里有博主昵称」不构成单独排除本目录的理由——
同一类信息已经在公开仓里了，只把决议挡在外面是自相矛盾的。

仍然不发布的是 `docs/LOCAL.md`：里面有本机 git 身份（公司邮箱）、
凭证文件的值形态示例、公司安全代理域名。那些是本机操作手册的内容，
不是项目知识。

本目录发布前逐份过 `tools/scan-leaks.js`：2026-09-17 实扫 17 份决议全部干净。
改写过的本机路径有 4 处（0007、0010 ×2、0011），改成 vault 内相对路径或
「本机那份源码」这类说法——决议的价值在推理过程，不在路径本身。
翻转的完整理由、删规则与豁免的界线、以及一次自伤记录见 [0017](0017-评审文档与决议目录全部发布.md)。
