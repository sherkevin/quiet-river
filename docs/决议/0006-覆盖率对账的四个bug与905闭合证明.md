# 0006 覆盖率对账的四个 bug 与 905 闭合证明

状态：Accepted（2026-09-13）

## 背景

用户问的是一句话：**「你确定你把我的知乎的关注列表都排查完一遍了吗」**

[0002](0002-筛选要算覆盖率，简介不能当唯一证据.md) 已经为这个问题立了规矩：
筛选要算覆盖率，简介不能当唯一证据。但那个脚本
（`tools/zhihu-coverage.js`）在真正跑起来对账的时候，连着露出四个 bug。
四个 bug 的方向不一样，有两个把「已扫」算少，有两个把「已排除」算多，
**合在一起的效果是让对账表既报假阳性又报假阴性，而且两边都看着像是对的。**

对账工具报假阳性会毁掉它自己的可信度：人会开始不信这张表，
然后连真漏网的也一起划掉。所以这四个 bug 值得单独记一条决议，
而不是塞进代码注释里就完事。

## 决策

### bug 1：「反向抽查」是个恒等式，什么都没查

旧代码对 188 个「靠简介文本排除」的人，用一个超宽词表（`AI`/`data`/`engineer`
都算）重扫一遍昵称 + 简介，输出「命中 0 人 → 无漏网」。

这个 0 是恒等式，不是发现：这批人之所以在这儿，正是因为他们当初被粗筛判成
「简介不含任何技术信号词」。用同一类正则再测一遍同一批文本，必然还是 0。
于是这一刀看起来在做反向抽查，实际什么都没查，而它输出的「无漏网」
恰恰是最容易让人停止怀疑的一句话。

实测代价：靠这个假阴性，184 人里有 18 个简介写得很含糊、两边都不沾的人
一直没被扫过。其中**张俊林**（NLP/推荐领域知名作者）的简介只写
「你所不知道的事」，旧逻辑判它「无漏网」。

改法：**文本排除要有正向证据才成立。** 简介里明确自陈另一个领域
（医学/美食/法律/历史/摄影/考研）的人，排除有据；简介含糊到两边都不沾的人，
排除没有证据，必须实扫。代码里落成两个正则：`WIDE`（技术/学术信号）和
`OUT`（领域外证据），两者都不命中且不在库里的，就是残余风险集合。

那 18 人已经组 batch16 实扫确认完，张俊林现在在库里。

### bug 2：昵称匹配两个工具各写一遍，给出相反结论

`coverage.js` 只把源名去括号（「科学空间（苏剑林）」→「科学空间」），
`rejudge.js` 两种都收（去括号的 + 括号里的）。结果是同一个人，
一个工具说「已入库」，另一个说「!! 未入库」——**苏剑林**就这么被报成待处理。

改法：抽到 `tools/lib/library.js` 的 `makeLibraryMatcher`，两个工具都引它。

### bug 3：子串匹配把不同的人判成同一个人

修 bug 2 的时候顺手发现，旧的子串匹配（`sn.includes(n) || n.includes(sn)`）
在真实数据上命中三个，**三个全是错的**：

- 「本质教育李泽宇」撞上库里的「泽宇」
- 「YouTube精选字幕」撞上「ACM RecSys（YouTube）」
- 「Vincent」撞上「VincentLee」

这个方向比 bug 2 更重：判成「已入库」的人会**从对账表里彻底消失，
没人再看第二眼**。判成「未入库」只是多一行待确认。

改法：判据分三态——确凿已入库（token 对上或昵称全等）/ 疑似（子串关系，
单独列出来给人确认）/ 未入库。另外抽名字时先排掉平台标签
（掘金、YouTube、B站、公众号…），因为源名括号里装的多半不是人名。

### bug 4：分母没对齐，闭合校验永远差 2

扫描集合里混进了 2 个不在关注列表的 token（**朱小强**、**缄默笔记**）。
calib 批是拿库内既有源做的，而库里有人是早先从别的入口收的、
或后来被取关了。把它们算进「实扫」，闭合校验就变成 907 != 905，
而那个 -2 会被当成 bug 去查。

改法：先按关注列表过滤扫描集合，不在列表里的单独打一行说明，不计入算式。

### 另外三处

- **`loadScanned` 的去重键错了。** 旧代码按 `itemCount` 取最大，
  但 `itemCount` 是接口返回的计数，`allTitles` 才是真正抓到的标题数组，
  退避续跑时两者会不一致。改成按 `allTitles.length` 取最大。
- **文件名清单写死到 result6。** 批次会一直加（batch8、batch9…、calib），
  写死的话每加一批就得改两处，迟早忘一处，对账数字悄悄偏小。
  改成正则 `^zhihu-(gap-result|shortlist|calib-result).*\.json$` 收全部。
- **`--emit-pending <N>`**：把残余风险集合直接写成待扫批次文件。
  做成脚本的一步而不是让人手抄 token，是因为残余集合会变——粗筛口径改一次、
  或 OUT 词表补一个词，这批人就换一个名单。手抄 18 个 token 必出错，
  而抄错一个就等于又留一个洞，且这个洞在账上看不出来。

### 905 的闭合证明

四个 bug 修完，`node tools/zhihu-coverage.js` 的输出是：

```text
关注总数 905
  标题级实扫（有内容证据） 734
  扫了但注销/无任何内容   18
  靠简介文本排除         153
  闭合校验 905 = 总数 OK
  （扫描集合里另有 2 个 token 不在当前关注列表，不计入上式：朱小强、缄默笔记）

残余风险（对 153 个靠简介文本排除的人）
  简介带技术/学术信号 0 人
  简介既无技术信号也无领域外证据 0 人 → 文本排除不成立，必须实扫

  文本排除全部有据，无残余风险。
```

734 + 18 + 153 = 905，退出码 0。三个数各自的含义：

1. **734 人**逐条拉过标题（每人最多 59 条，合计 29,357 条标题），
   用共用词表判分，过线的全部人工看过标题样本，收与不收都记在
   [0003](0003-收录范围扩到机器学习干货与数学.md)、
   [0004](0004-词表要随批次修，判据是一手还是转述.md)、
   [0005](0005-收录范围再扩到跨领域干货，判据加一条导流.md) 里。
2. **18 人**扫了但账号注销或没有任何内容，这是实扫得到的结论，不是推断。
3. **153 人**靠简介排除，且**每一句简介都人工过了一遍**。
   这批人的简介长这样：口腔颌面外科医生、江苏省人民医院主任医师、
   美食答主王大厨、古军事史、税法王如僧律师、烘焙入坑10年、
   中国12种本土猫科动物、《睡眠公式》作者、电脑博物馆站长。
   没有一个是技术/学术领域内的人。

范围在 [0005](0005-收录范围再扩到跨领域干货，判据加一条导流.md) 扩到
量化金融/数据分析/CV/NLP/RL/多模态之后，这 153 人又复查了一次：
用一个专门的新范围信号词表（量化/金融工程/精算/数据分析/计算机视觉/
算法工程师/多模态/推荐算法/运筹/最优化/PhD/研究员…）去测他们的简介，
**命中 0 人**。还专门测了一种更隐蔽的形状：简介同时命中「旧 OUT 财经支」
和「新范围信号」的人（比如「量化投资研究员」），这种人会被
`!OUT && !WIDE` 的逻辑静默判成「有据排除」，永远不会进残余风险集合。
实测也是 0 人。

财经相关的简介确实有几个，但没有一个是做研究的：
《高胜率价值投资》作者（散户读物）、资深股票投资经理、财经博主、
财经媒体号、前私募基金风控（简介主体是「冥想爱好者」）。
**范围里有量化，不等于关注列表里有量化**，这条也记在 0005 的后果里。

### 一个必须记下的教训：提问假阳性

**大雄的WiFi 被判 68%**，在整张过线名单里排第三，看着是最该收的人。
实拉他的专栏文章，**只有 2 篇**：「定性绘制结构变形图系统学习」（2023-05）
和「向量的叉乘」（2020-11，他自己写「非常基础的解释」）。停更三年。

那 68% 是这么来的：`lib/adapters.private.js` 把 articles 和 answers 两路合并，
answers 那一路的标题用的是 `question.title`——**提问的标题，不是作者自己起的标题**。
于是他回答的那些提问全被算成了他的干货：

> 「如何计算下图中的矩阵的 n 次方？」「矩阵 A 中行与行交换后得到的新矩阵 B
> 和原矩阵 A 有什么关系？」「线性代数还有好多不会，后天就要期末考了，
> 还有机会过嘛?」「这个第（1）题怎么求特征值的？」
> 「线性代数题,答案是 5/4、1/4、-1/4、-1/4，可以帮我看看这个怎么做的吗？」

**15 条「干货」里 15 条全是提问标题，一条陈述句都没有。**
他那 2 篇真文章（「定性绘制结构变形图系统学习」「向量的叉乘」）反而没进
干货计数——一篇是结构力学，一篇连技术词都没命中。
于是一个回答线性代数作业题的人被判成数学博主，判到全库第三高，
而他真正写的内容一篇都没被算进去。

根因不是词表错——那些标题确实全是线性代数，词表判得对。
根因是**分母的语义混了**：articles 的标题是作者对自己内容的概括，
answers 的标题是别人提的问题。两者混在一个数组里算比例，比例就没有意义了。

这个洞还会朝反方向咬人：一个写严肃文章、但随手回答生活问题的人，
几十条生活问答会把分母冲大，分数被压到线下。
所以 [0005](0005-收录范围再扩到跨领域干货，判据加一条导流.md) 里判定
边缘候选人时，凡是分数和内容对不上的，都单独拉了一次
**只含 articles 的口径**重判：

| 人 | 混合口径 | 只看文章 | 结论 |
| --- | --- | --- | --- |
| 大雄的WiFi | 68%（15/22） | 2 篇，都基础 | 假阳性，不收 |
| master学堂 | 50%（17/34） | 65%（13/20） | 分数是真的，但正文是付费墙桩，不收 |
| 陈东文 | 12%（7/59） | 30%（6/20） | 假阴性，但 20 篇里 6 章是连载小说，不收 |
| 来一块葱花饼 | 35%（14/40） | 40%（8/20） | 真，收 |

**规矩**：过线名单上凡是「分数高得可疑」或「分数低得可疑」的人，
都要拉一次 articles-only 口径复核，不能只看混合数字下结论。

## 后果

- `tools/zhihu-coverage.js` 现在是可复核的：不发请求、不读 cookie，
  只读已落盘的 JSON，所以能进公开仓，也能反复跑。退出码只对
  「还没干完的活」触发（残余风险非空、或算式不闭合），
  「过线未入库」不计入退出码——按 [0003](0003-收录范围扩到机器学习干货与数学.md)
  的流程，那一档本来就要人眼看标题才决定，人眼看完排除掉的号会一直留在
  名单里，它是「已经看过、决定不收」的记录，不是待办。
- `tools/lib/library.js` 成了「这人是不是已在库里」的唯一判据，
  `rejudge.js` 和 `coverage.js` 共用。`test/library.test.js` 25 个用例
  把 bug 2 和 bug 3 各钉住一个方向（漏报与误报），改判据时会先炸测试。
- `tools/zhihu-shortlist.js` 自己那张 `TITLE_CORE`（搜广推口径）已经删掉，
  改成引 `wordlist.js` 的 `REC`。这是 0004 遗留 #3，两个工具各拿一把尺子
  导致「定西」被 shortlist 认出是搜广推博主（命中 MMOE/ESMM/DIN）、
  却被 rejudge 判到 15% 的那个问题，现在没有了。
- `tools/zhihu-gap-queue.sh` 串行跑批次（知乎约 17 请求/15 秒就 403，
  两个进程一起跑会把 cookie 打废），每批跑完检查退避次数，
  超过 5 次就停下不往下跑——免得带着半截结果一路错下去。

## 遗留

1. **articles-only 口径没有进脚本。** 现在是人手工拉一次复核。
   如果要自动化，得在扫描时把 articles 和 answers 分开落盘
   （`articleTitles` / `answerTitles`），然后 `judge` 只用前者算主指标。
   那是 `tools/zhihu-shortlist.js` 的改动，要重扫 734 人，代价大，
   暂时靠人工复核兜住。
2. **`OUT` 词表里的财经支现在是可疑的。** [0005](0005-收录范围再扩到跨领域干货，判据加一条导流.md)
   把量化金融纳入范围之后，「简介写着金融/投资/证券」不再是领域外证据。
   这一批复查过 153 人，确认没有漏网的（命中新范围信号的 0 人），
   但**规则本身没改**：下次粗筛口径变动或关注列表更新时，
   这条会再次静默吞人。改法是给财经支加一个例外：
   简介里同时出现量化/研究/建模这类词时不算领域外。

   上面这条在写决议的时候顺手改掉了，不再是遗留。改法是让 `WIDE` 压过 `OUT`：
   `loose = wideHits + noEvidence`，也就是简介只要带技术/学术信号，
   不管 OUT 怎么说都进待扫集合，并且计入退出码。
   理由是正向的技术信号比领域猜测更有分量——「量化投资研究员」这句简介，
   OUT 看到的是「投资」，WIDE 看到的是「量化」，后者才是关于他做什么的陈述。
   改之前这条 bio 会被判成「有据排除」，既不打印成待办也不触发退出码。
   改完在当前数据上仍是 0 人（153 人里确实没有一个简介带技术信号），
   但下次关注列表更新时这个洞不会再张开。
