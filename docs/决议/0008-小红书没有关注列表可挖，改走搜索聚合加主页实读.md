# 0008 小红书没有关注列表可挖，改走搜索聚合加主页实读

状态：Accepted（2026-09-13）

## 背景

知乎那批（决议 0001-0007）的入口是「我的关注列表」：905 人全量排查，挖出 111 个源。
用户接着要求「小红书的博主也看一下，再多推一点进来」。直觉做法是照搬知乎路径——
翻关注列表。

**这条路在小红书不存在。** 登录态实测（`opencli xiaohongshu creator-profile` 与个人主页
UI 双路核对）：本账号关注数 = 3，就是库里已有的楚风、fifi的算法日记、左眼。关注列表
没有增量可挖，「排查关注列表」这个动作在小红书是空转。

## 决议

小红书候选改走**搜索聚合 + 主页实读**两段式：

1. **搜索聚合**：8 组领域词（生成式推荐 / 推荐算法工程师 / 搜索算法 / 广告算法 /
   大模型训练 / 强化学习 RLHF / 多模态大模型 / 量化投资 研究）各取 20 条，
   `opencli xiaohongshu search` 的返回带 `author_url`（含 24 位 user id），
   按作者聚合命中次数与最高赞，得 134 个候选作者。原始返回落盘
   `data/experiments/xhs/search-*.json`。
2. **主页实读**：对聚合筛出的 21 个候选逐个 `opencli xiaohongshu user <id> --limit 20`
   拉主页笔记（落盘 `data/experiments/xhs/user-*.json`），按 0001/0005 的三条判据实读
   标题与更新形态后定收不收。干货标题抽样与 §4 各表同尺：`tools/lib/wordlist.js` 的
   `judge()`。

判据沿用不新造：一是作者自己在做不是转述；二是营销文体与面试辅导号不收；三是正文本身
是内容不是引流桩。

## 结果

收 10 人：Cici学算法、江河（二人主线是搜广推，并进 Sources.md 第 1 节总表）、
Panda师兄的AI笔记、DailyLLM、Hunter、梁定康、锦砺、具身漫步、算法工程师成长记、
Coral quant（跨领域 8 人记在 Sources.md 第 4 节新增的小红书小节）。
Coral quant 让「金融量化」这个 tag 从空变成 1 源——0005 里「量化在知乎是零」的结论
限定的是知乎关注列表，不是全平台。

排除 9 人，逐个理由：

| 作者 | 排除理由（对应判据） |
|---|---|
| RessMatthew | 讲解系列止于 2025-11（RLHF/Transformer/解码策略四篇是入门级），2026 年起全是面试记录与抽奖，主体已转向 |
| 低头的人 | 停更：2026-07 最后一条是「毕业快乐！」，RL 笔记系列止于 2025-08，夹杂生活帖 |
| 只此青绿 | 停更（近 90 天 0 条），且主体是论文写作与读研生存经验，不是技术干货 |
| 小盖 | 行业评论与观点号：日更但零技术密度，属转述不是自己做（判据一） |
| 持续学习妹妹 | 撞名：搜索命中的 RLHF 图解帖不是这个号，主页是社区物业帖 |
| AI旅行者 | 「2026 XX 面试全攻略」系列量产号（判据二） |
| 码上成长 | 停更（近 90 天 0 条），全号仅 5 条 |

另核 2 个机构号**不重复入库**：美团技术团队、快手技术的小红书号促销与赠票帖占比高，
且二者在库里已有更好的通道（tech.meituan.com 的 atom、快手技术 CSDN RSS）。
同一作者多平台时只订内容最全的那一路，这条与知乎/公众号同名源的处理一致。

## 后果

- 库从 160 源涨到 170 源 / 4781 条；小红书 3 源 60 条 → 13 源 253 条。
- Sources.md 第 4 节新增「小红书跨领域」小节与「核验未收」记录；第 2 节通道矩阵的
  小红书行补一句：搜索返回带 author id，可反查候选。
- 搜索聚合的天花板要记住：它只看得见**被搜到的词**覆盖得到的号。知乎那批有关注列表
  兜底（用户已经用脚投过票），小红书这批没有——所以这 10 人是「检索能及」的下界，
  不是「用户兴趣」的全集。下次要扩，先问用户要他刷到过但没关注的号，比换搜索词有效。
