# 当前里程碑：先接通来源与更新展示

用户于 2026-09-17 调整顺序：全文提取、阅读器归档、高亮与笔记后移。
本文件改变执行优先级，不删除既有功能和数据，也不回退整体产品目标。

## 本阶段交付

1. 保留现有 271 个博主及标签；不把公共精选流替代关注列表。
2. 跟踪知乎、小红书、博客、公众号等各平台的新增标题、作者、来源、时间和原文链接。
3. 页面打开/刷新触发更新检查，自动任务继续运行；遵守缓存、共享凭证与平台退避。
4. 按平台、作者和标签展示；默认进入时间线，优先打开原文，不等待全文或批注系统。
5. 来源页区分登记、通道已启用、历史检查成功和当前健康；缺授权不算接通。
6. 没有发布时间则明确未知；最后成功检查时间不能用最新文章发布时间代替。
7. 复用已有逐作者 RSS 和已验证匿名接口；第三方逐博主通道仍允许。

## 本阶段不开发

不扩展正文提取、图片归档、批注、笔记导出、复杂推荐和日报算法。
保留已运行的阅读组件，不擅自删除旧正文、笔记或停用现有访问入口。
不得为了元信息接入主动抓每篇文章全文；Feed 自带正文可原样保留。
不猜造公众号 Feed 或 X 的转发哈希；不擅自复制其他设备的登录态。

## B站4源接入路线收敛（2026-09-17）

4个既有B站来源均已核对为 `/bilibili/user/video/:uid`，不是专栏/动态等其他路由。
ECS 隔离验证当前普通 RSSHub 镜像：192 MiB 内存上限不能完成启动，256 MiB 时约占246 MiB；真实 B站 route 因 ECS 对空间/WBI接口返回412而不能出 feed。
因此不为这4个源在2C2G主机增加RSSHub/Chromium常驻负载，也不把B站Cookie迁到ECS。

Shervin OpenCLI 1.8.7 的 `bilibili user-videos` 对已订阅作者真实 limit=2 检查成功，原链与日期完整。
实现方向固定为现有 desktop collector：保持原 channel ID，UID 从既有 feed path 解析，单次最多20条，只上传元信息。
生产验收标准仍是4/4来源产生真实 `last_success` 与条目；代码/单点探针通过不等于4/4已经完成。
