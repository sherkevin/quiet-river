# 当前里程碑：先接通来源与更新展示

用户于 2026-09-17 调整顺序：全文提取、阅读器归档、高亮与笔记后移。
本文件改变执行优先级，不删除既有功能和数据，也不回退整体产品目标。

## 本阶段交付

1. 保留现有 271 个博主及标签；不把公共精选流替代关注列表。
2. 跟踪知乎、小红书、博客、公众号等各平台的新增标题、作者、来源、时间和原文链接。
3. 页面打开/刷新触发更新检查，自动任务继续运行；遵守缓存、共享凭证与平台退避。
4. 按平台、作者和标签展示；默认进入时间线，优先打开原文，不等待全文或批注系统。
5. 来源页区分登记、通道已启用、历史检查成功和当前健康；缺授权不算接通。
6. 没有发布时间则明确未知；最后成功检查时间不能用最新文章发布时间代替。
7. 复用已有逐作者 RSS 和已验证匿名接口；第三方逐博主通道仍允许。

## 本阶段不开发

不扩展正文提取、图片归档、批注、笔记导出、复杂推荐和日报算法。
保留已运行的阅读组件，不擅自删除旧正文、笔记或停用现有访问入口。
不得为了元信息接入主动抓每篇文章全文；Feed 自带正文可原样保留。
不猜造公众号 Feed 或 X 的转发哈希；不擅自复制其他设备的登录态。

## 本批实现与验证范围

- 默认进入全部更新，并以打开原文为卡片主操作；不等待归档、高亮或正文补抓。
- 添加全局平台筛选；列表与刷新都限制到所选平台，作者与标签筛选继续有效。
- 来源页增加名称/标签搜索、启用/待接入/异常筛选，以及最近尝试和成功检查时间。
- 页首分别列出已登记博主、有启用通道、曾检查成功；成功次数不等于全天稳定性。
- 新增知乎/小红书主页时严格提取本人选择的作者 ID；相似恶意域名不匹配。
- 可给既有作者补充 Feed、重载服务器通道配置；不能从前端自行开启浏览器或冒充授权。
- 为已有掘金作者接入原项目的匿名列表能力，通过现有队列导入元信息，不抓每篇正文。
- 掘金仍有下一页时结果为 SUCCEEDED_PARTIAL，页面明确显示部分列表，不声称完整覆盖。
- 为现有 Recsperts 播客通过 Apple ID 1587222271 核对官方返回的 Feed，保持作者和标签。
- 使用既有经过鉴权的状态接口，不增加独立来源覆盖 API。

### 后续接入顺序

先完成已有博客/公众号转发通道的逐源健康与展示；再接通知乎、小红书授权采集。
17个缺出口公众号分别找准确的逐作者通道，不能猜地址或用其他作者替代。
X的转发宿主故障单独处理，不让重复超时拖住其他来源；不自动购买付费API。
DataFunTalk缺准确主页，Semantic Scholar分页/更新时间仍待确认，不以名字猜测通道。
缺授权时只在安全配置环境内完成授权，Cookie和私钥不提交、不贴聊天。
本批不增加浏览器负载、不修改订阅之外的作者，不继续开发阅读/笔记能力。
