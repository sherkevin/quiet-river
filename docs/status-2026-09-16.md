## 关键问题排查记录

这一节是今天最值钱的部分：四个假象互相矛盾，每个都曾把排查引向错误方向。

| 假象 | 真因 | 解法 |
| --- | --- | --- |
| 手机访问 80 端口 `ERR_TIMED_OUT`，Mac 却拿到 200 | 大陆地域 ECS 未做 ICP 备案，阿里云在边缘对公网直连 80 丢包；Mac 的 200 是公司办公网透明代理代答的 | 服务改监听 4321，实测公网可通 |
| 早先「nc 探测 80 端口通」 | 安全组入方向默认只开 22/3389/ICMP，握手是代理代答的 | 用 aliyun CLI 补开 80 与 4321 |
| 「ECS 上 curl 自己公网 IP 得 200」当作公网已通的证据 | 实例访问自己的公网 IP 走 hairpin，不经过边缘拦截，是假证据 | 公网可达性一律用第三方出口验证：GitHub Actions 探针 workflow（`.github/workflows/probe.yml`，workflow_dispatch 触发） |
| Mac 上 `cloudflared` 一启动就被 SIGKILL、tailscale 同样被杀 | 不是崩溃：`trycloudflare.com`、`lhr.life` 被办公网安全代理的域名策略拦截（返回中文 403 拦截页） | 隧道改在 ECS 上跑，ECS 出口干净 |
| ECS 上 curl 自己的隧道地址返回 000 | 隧道域名 DNS 只回 IPv6，而 ECS 无 IPv6 连通 | 自测加 `-4`；手机等真实客户端不受影响 |
| 中继 curl 全通、浏览器却「连不上后端」 | **FC 网关自己会按请求 Origin 注入一整套 CORS 头**，后端 server.js 也发了一套，两套叠在一起 `Access-Control-Allow-Origin` 出现两次，浏览器直接判非法。curl 不看 CORS，所以只有浏览器能暴露 | 中继丢弃上游所有 `access-control-*` 头，只留网关那套（网关按请求 Origin 回显，预检与实请求都正确）。`tools/deploy-relay.sh` 的自检 1 把「CORS 头只出现一次」变成硬闸 |

判别连通性的方法论也固化进了 README：**验证公网可达性要用干净出口**（在 ECS 上 curl 自己的公网 IP），并访问一个「安全组放通但无服务监听」的端口看是立即 refused 还是空响应/超时；本机办公网观测到的 200 一律先怀疑。同理，**跨域链路要用真浏览器验证**：curl 不执行 CORS 策略，头重复这类问题它永远看不见。

## 单一全网络入口（FC 中继）

直连 IP 永远凑不齐所有网络：办公网代理只放 80、运营商网对未备案 80 丢包、办公网域名策略拦掉几乎所有隧道域名（trycloudflare、pinggy、workers.dev、vercel 全灭）。实测唯一在所有网络都放行的域是阿里云 FC 的默认域 `*.fcapp.run`。于是在 FC 上放了一个 256MB 的 Node 中继函数 `qr-relay`（代码在 `tools/relay-fc/index.js`），把任意请求原样转给 ECS：

- 办公网、运营商网、境外实测全通；按调用计费，这个量级约等于免费。
- FC 默认域禁止任何 3xx 重定向（`ExternalRedirectForbidden`，连指向自己都拦），中继把上游 302 降级成 200 + meta refresh，Set-Cookie 照旧下发，登录流程不受影响。
- FC 网关把数组响应头序列化成 JSON 串（`Set-Cookie: ["..."]`），中继把单值头转回字符串。
- **FC 网关会自己注入 CORS 头**（按请求 Origin 回显，含 `Access-Control-Allow-Credentials: true`）。后端那套必须在中继里丢掉，否则重复头让浏览器拒绝所有跨域请求。这是「curl 通、浏览器不通」的根因。
- FC 默认域给每个响应加 `Content-Disposition: attachment`，所以**中继地址不能当网页直接打开**（会变成下载文件），它只给 Pages 上的前端当数据接口。网页入口永远是 Pages 那个链接。
- method 在 `event.requestContext.http.method`，不在事件顶层；事件本身是 Buffer 装的 JSON。这三条是 FC 3.0 Node 运行时的真实契约，代码注释里都写了。

活中继站的口令模型：跨域带不了 cookie，口令存浏览器 localStorage、用请求头 `x-qr-token` 送（`lib/access.js` 同时接受 cookie、query、header 三种）。第一次打开 Pages 链接会弹口令框，输一次即可；口令只存在那台设备的浏览器里，不进任何文件。

## 边界与已知问题

- ECS 上没有知乎/小红书的凭证与私有适配器，这 128 个源停在随包快照时刻并进问题栏，旧内容保留。这是设计形态（机房 IP 段更易触发平台风控），不是故障；要全活按 `docs/deploy-parity.md` 在服务器补凭证，但先想清楚风控代价。
- cloudflared quick tunnel 的地址在隧道进程重启后会变。要固定地址需要 named tunnel 加自己的域名，那是备案或境外域名的事，今天没做。中继形态上线后隧道已不是必需路径，`qr-tunnel` unit 留着仅作兜底。
- 那对阿里云 AccessKey 曾出现在聊天记录里。建议去 RAM 控制台禁用或换成仅 ECS 权限的子账号 key，然后更新本机 `~/.workbench/config.json`。
- ECS 全量缓存 4.2MB，`/api/state` 单次响应约 4.9MB，蜂窝网络下首屏偏慢（实测经中继约 10-25 秒）；后续可做分页或按视图裁剪。**页面打开后会自动触发一次后台抓取**（`maybeAutoRefresh`，距上次抓取不足 2 分钟则跳过）；非 force 抓取尊重各平台的 `HOST_MIN_RECHECK_MS` 重抓周期，半小时内重复开页不会重复打第三方。
- `.codex-renders/`（Codex 桌面端会话渲染产物，会原样带着对话里出现过的口令）已加入 `.gitignore`；此前它未被忽略，属于潜在泄漏面，现已关闭。
